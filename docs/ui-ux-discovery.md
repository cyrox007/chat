# PubChat — Discovery UX extension

## Назначение

Discovery должен помогать найти живое место для общения, а не создавать новый рейтинг популярности.

## Карточка Space

Порядок визуального веса:

1. название, purpose и краткое описание;
2. атмосфера/appearance;
3. живой социальный контекст;
4. «Почему здесь»;
5. ближайшая Activity/Event;
6. join/open action.

Recommendation reason — объяснение, а не badge статуса.

## «Почему здесь»

- максимум три причины;
- короткий человеческий текст;
- не показывать числовой score;
- не показывать внутренние коэффициенты алгоритма;
- не использовать формулировки вроде «№1», «топ», «лучший» без объективного отдельного контекста;
- gift/support count не используется как причина;
- sponsored/paid recommendation в текущем продукте отсутствует.

## Upcoming context

Ближайшая Activity/Event показывается только когда backend включил её в projection. Frontend не пытается самостоятельно обходить privacy и получать скрытые данные дополнительным запросом.

## Filters

Search, purpose и tags остаются явными user controls. Персонализация не должна делать фильтры декоративными: выбранный фильтр обязан реально ограничивать выдачу.

## Diversity

Разные форматы Spaces могут перемешиваться для уменьшения однообразия. Diversity не должна подменять запрос пользователя и не может вернуть privacy-ineligible Space.

## Calm design

Запрещены:

- relevance progress bars;
- popularity score;
- paid boost marker без реального отдельного рекламного продукта;
- flashing «trending» states;
- искусственный urgency;
- leaderboard карточек.

## Mobile

На narrow viewport reasons и upcoming располагаются внутри карточки в одну колонку. Они не должны вытеснять основное действие «Открыть / Войти / Подать заявку» ниже первого экрана карточки без необходимости.

## Accessibility

- reasons доступны как текст, не только цвет/иконка;
- upcoming time имеет понятный текстовый контекст;
- chips не должны выглядеть как кнопки, если они не интерактивны;
- keyboard/focus flow сохраняется для filters и card actions.
